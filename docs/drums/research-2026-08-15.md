# Drums research digest — 2026-08-15

Condensed from four research passes (repo conventions, drum pedagogy, notation/MIDI tech,
market feature analysis), web-verified 2026-08-15. Feature specs under `features/` cite this
file instead of repeating sources. Confidence flags kept where the research had them.

## 1. Pedagogy — the verified progression (step 0 → mid-intermediate)

Cross-checked against the Drumeo Method (8–10 levels), Rockschool Drums (Debut–Grade 5),
Trinity Rock & Pop, PAS/Vic Firth rudiment guidance, and the canonical method books
(Stone *Stick Control*, Reed *Syncopation*, Wessels *A Fresh Approach to the Drumset*,
Igoe *Groove Essentials*, Appice *Realistic Rock*, Chester *The New Breed*).

**Technique order:** posture/kit setup → matched grip (German-leaning start; American as the
converged default; French for finger control later) → four stroke types (full, down, tap, up)
→ rebound control → heel-down bass drum first, heel-up introduced once control exists →
hi-hat foot → **Moeller is intermediate, not beginner** (requires rebound control first).

**Rudiment order (Wooton/Vic Firth four-tier, not PAS list order):**
- Tier 1: single stroke roll, multiple-bounce (buzz) roll, double stroke roll, single
  paradiddle, flam, drag. Multiple sources converge on these six as the beginner set.
- Tier 2: single stroke four/seven, double/triple paradiddle, paradiddle-diddle, 5/7/9-stroke
  rolls, flam tap, flam accent, single drag tap.
- Tiers 3–4 are upper-intermediate/advanced — out of primary scope.
- Tempo practice: start ~60 BPM, +5 BPM increments gated on a sustained clean run (commonly
  ~60 consecutive clicks), even volume between hands. Beginner band roughly 60→100 BPM.

**Reading order:** quarters/quarter rests → 8ths → 8th rests → 16ths → dotted → triplets →
syncopation → odd meters (Grade 5+ territory). *Syncopation* (Reed) is structured exactly
this way.

**Coordination order:** 8th hi-hat ostinato alone → add kick (money beat) → add backbeat →
16th kick permutations → hi-hat foot on 2&4 → hi-hat openings → ghost notes → jazz ride +
comping (intro of 4-way independence; full 4-way is the intermediate/advanced boundary —
*New Breed* territory).

**Styles order:** straight 8th rock → half-time and 16th-note rock → blues shuffle (first
swung feel) → funk (needs ghosts + 16th kick) → jazz swing → latin/bossa/samba. 6/8 and 12/8
arrive mid-way (Drumeo level 5).

**Fills:** start immediately after the first solid groove; first fills are single-voice 8th
notes over 1 beat; the taught skill is leaving and re-entering the groove on beat 1.
Vocabulary develops on two axes (PAS): one rhythm voiced many ways around the kit; one
voicing given many rhythms.

**Dynamics order:** accents → rimshot (RS Grade 4) → ghost notes → cross-stick (Drumeo L4,
RS Grade 5). Ghost notes + accurate rimshots are an explicit beginner→intermediate marker.

**Metronome methods drummers actually use:** tempo ladder (+3–5 BPM on clean, drop on miss),
gap click (mute N bars, drift revealed at return — Benny Greb's signature exercise),
subdivision clicks, click on 2&4 only, playing to real music as the application step.

**Beginner/intermediate boundary (Drumeo + teaching-community consensus):** comfortable ghost
notes and consistent rimshots, metronome confidence, dynamic limb independence, can learn a
pop song relatively fast by ear, improvises simple parts. That boundary is this roadmap's
**exit condition**.

**Session structure (30 min beginner):** 5 warmup / 5 timing / 10 grooves / 5 rudiments /
5 play-along. Consistency beats length; 20–30 min daily suffices.

**Theory a drummer needs:** note values + 4/4 (day one) → song form verse/chorus (as soon as
songs appear) → 12-bar blues (with shuffle) → 6/8, 12/8 (mid) → chart reading: slash
notation, repeats, D.S./coda (intermediate) → AABA (mid-intermediate) → polyrhythm 3:2 intro
(upper edge of scope).

**Level calibration used by the drums curriculum (docs/drums/features/DR-16):**
Drumeo levels 1–7 and Rockschool Debut–Grade 5 map onto our D1–D6; RS Grade 5 skills
(4-way coordination, Texas shuffle, cross-stick fluency) mark the top of scope.

## 2. Notation — standardized drumset notation (Weinberg/PAS)

5-line staff, percussion clef, positions read as if treble clef (this is also how MusicXML
computes them). Agreed conventions:

| Voice | Position | Notehead |
|---|---|---|
| Crash | above staff | x |
| Hi-hat (hands) | space above top line | x (o above = open, + = closed) |
| Ride | top line | x (bell = diamond) |
| High tom | 4th space | oval |
| Snare | 3rd space | oval; ghost = parenthesized; cross-stick = x on snare position |
| Mid tom | middle line | oval |
| Floor tom | 2nd space | oval |
| Kick | bottom space | oval |
| Hi-hat foot | below staff | x |

Two voices: **hands stems up, feet stems down** (reliable, universal).
Low confidence / verify against the PAS guide before freezing glyphs: exact rimshot glyph and
the cross-stick alternative (slashed circle) — secondary sources disagree.

## 3. MIDI — GM percussion map and real e-kit behavior

GM channel 10 (0-indexed channel 9; status bytes `0x99`/`0x89`). Core kit subset:

| Note | Sound | Note | Sound |
|---|---|---|---|
| 35/36 | Kick (acoustic/std) | 46 | Open hi-hat |
| 37 | Side stick | 47/48/50 | Mid/hi-mid/high tom |
| 38/40 | Snare (acoustic/electric) | 49/57 | Crash 1/2 |
| 41/43/45 | Floor/low toms | 51/59 | Ride 1/2 |
| 42 | Closed hi-hat | 53 | Ride bell |
| 44 | Pedal hi-hat | 55 | Splash |

**Real kits do not stay inside GM (35–81):**
- Roland TD: extended zone map — 22/26 (hi-hat edge closed/open), 27/28 (aux), 40 (snare
  rim), 50/47/58 (tom rims), 53 (ride bell), 55/52/57/49 (crash zones), 59 (ride edge).
  Medium confidence (community-transcribed; spot-check against Roland's TD-17 note-map page).
- Alesis (Nitro/Crimson): explicit **GM Mode toggle** — GM map when on, proprietary when off.
- Yamaha DTX400K: **ride = 83** (outside GM range), toms 43/51/49, splash 47. Not GM by
  default.

**Hi-hat pedal:** continuous **CC#4** 0–127 alongside note-ons; TD-17's closed threshold
fixed at 90, configurable on higher modules. Some budget kits never send separate open/closed
notes — the CC is the only truth. **Cymbal choke:** polyphonic aftertouch (`0xA0`–`0xAF`),
not note-off. **Note-off quirk:** velocity-0 note-on must be treated as note-off (spec, and
Yamaha does this). **Durations:** drum note-offs arrive near-instantly; notes are events, not
held. **Double triggers:** module-side retrigger cancel exists; app-side ~10–30 ms per-pad
debounce is a reasonable second layer (engineering judgment, no spec'd number).

**Velocity semantics:** ghosts land roughly 30–50, normal hits 90–100 — low velocity is
signal, not noise; per-pad minimum-velocity gate should be configurable, not hardcoded.

**Latency:** USB MIDI sub-1 ms; BLE-MIDI adds ~3–50 ms and jitters (typically 5–15 ms).
`MIDIMessageEvent.timeStamp` is a `DOMHighResTimeStamp` — sufficient for scoring.
Consequence: scored modes should recommend USB; BLE gets a calibration offset and a warning.

## 4. Hit-window calibration (from rhythm games/apps)

| System | Full-credit window |
|---|---|
| osu!taiko OD0→OD10 | ±48 → ±18 ms ("Great"); ±108 → ±48 ms ("Good") |
| Fortnite Festival | ≈ ±25 ms (community) |
| Clone Hero | ≈ ±140 ms (deliberately generous) |
| Melodics | on-time/early/late colors, no published ms |

Practical: learning app starts ~±100 ms "hit" with early/late shading, tightens per level
toward ±40–50 ms. Always show the signed ms deviation — a 2025 Frontiers in Psychology study
found objective numeric feedback beats vague judgment and counteracts self-deception.

## 5. MusicXML + OSMD state

- MusicXML: `<unpitched>` + `display-step/display-octave` (position only, not pitch);
  playback instrument comes from `<midi-unpitched>` on the matching `<score-instrument>`,
  never from display position; `<notehead>` supports `x`, `circle-x`, `diamond`, etc.;
  hands/feet separated by `<voice>` + explicit `<stem>`.
- OSMD (as of v1.9.4, Jan 2026): percussion staves render (clef, x noteheads,
  one-line cutoff via `PercussionOneLineCutoff`), and `CustomNoteheadVFCode` passes raw
  VexFlow glyphs for anything unmapped. **Known open gaps (issue #887):** ghost-note
  parentheses not respected, open-hi-hat "o" not recognized, "+" placement wrong, flam grace
  notes dropped, roll/tremolo lines too thin. Issue #1437: slash noteheads oversized.
- Alternatives: alphaTab has the strongest out-of-box percussion (notation + drum tab +
  synth) but is a whole parallel stack; VexFlow direct means reimplementing OSMD's layout.
- **Consequence adopted by this roadmap:** trainer surfaces (grooves, rudiments, reading)
  use our own SVG groove renderer where ghosts/sticking/hh-state are first-class; OSMD is
  reserved for full charts (DR-26), with the escape hatch + a decision gate to alphaTab if
  #887-class gaps block chart quality.

## 6. Market — what exists, what to copy, what to avoid

Feature matrix over Drumeo, Melodics, Yousician, GrooveScribe, Drum School, DrumGenius,
PolyNome, Gap Click, Aerodrums, Clone Hero/RB, Moises, Drumbitious, Beatlii. Highlights:

**Copy:** Melodics' per-note early/late colors + wait mode + section loop + BPM slider;
GrooveScribe's grid editor with URL-encoded shareable state; PolyNome's gap click and
random-mute metronome modes; rudiment apps' auto tempo-ramp ("+N BPM every M bars on
success"); Beatlii's togglable notation ↔ falling-notes view; Drumeo's leveled curriculum
shape; Moises' section-loop play-along ergonomics.

**Market gap (differentiator):** nobody does true spaced repetition over rudiments/grooves —
every "smart" feature found is a tempo ramp or a stats log. This app already owns `core/srs`.

**Design around documented complaints:**
- Hi-hat pedal mis-triggering / threshold mismatch (Melodics + e-kit forums) → hi-hat
  calibration is a first-class setup step (DR-02/DR-08).
- Double-sound latency (module voice + app voice) → let the user silence one side; prefer
  scoring by MIDI timestamps, never audio.
- "Scoring feels unfair" (Yousician) → show which pad, which ms, which velocity was received.
- Passive video-course fatigue (Drumeo) → active play→score→retry loop is the primary
  surface; prose/diagrams stay short.
- Apps can't see technique (all) → say so honestly; checklists and self-video prompts, no
  fake technique grades (DR-18).
- Catalog vanishing mid-use (Drumeo 2024 purge) → all content bundled and local.

## 7. Practicing without an e-kit (browser reality)

- Keyboard-key drumming is proven web practice (playdrumsonline, ButtonBass): QWERTY rows
  → pad groups; negligible latency, but **no velocity** — dynamics need a synthetic
  channel (modifier keys).
- Mic tap/onset detection is feasible via Web Audio (`AudioWorklet` energy/spectral-flux):
  default end-to-end browser audio latency measured ~**55–67 ms**, reducible with
  `latencyHint: 0` and disabled echo-cancellation — fine for generous windows, too
  jittery for tight ones without per-user calibration. "Did a hit happen" is
  solved-enough (open-source onset detectors exist); "**which** drum was hit" from one
  mic is a separate ML-classification feature (Melodics ships it with a per-drum
  calibration flow).
- Touch pads: straightforward, same no-velocity limitation (Pointer `force` support is
  inconsistent).

## 8. Repo facts the plan builds on

- `check-docs-budget.mjs` caps only ROADMAP.md/CLAUDE.md/PROCESS.md — `docs/drums/**` is
  free.
- Router: `ScreenId` union + hand-rolled history routing (`src/app/shell/route.ts`,
  `routing.ts`, `Shell.tsx` `NAV_ITEMS`/`NAV_GROUPS`/`renderScreen`). An instrument axis is
  a new concept above `Route`, with its own URL segment.
- Input: `MidiInput` port (`src/core/ports/midi.ts`) normalizes events;
  `playableInput.ts` merges hardware + on-screen input into one stream — the drum input
  stack should mirror this shape.
- Content: curriculum as typed TS data (`src/content/curriculum/`), scores as `?raw`
  MusicXML parsed by `parseMusicXml` at the untrusted edge; graded pieces carry provenance
  tiers.
- State: one Zustand slice per domain + shared `persistence.ts` hydration; core stays pure
  (no DOM/Date.now/Math.random — enforced by eslint).
- Reusable cores: `core/srs`, `core/timing` (metronome/transport), `core/curriculum` model,
  `core/progress` (levels/streak/export), `core/rhythm` (tap grading concepts),
  `core/practice` matcher patterns (piano-specific but the shape transfers).
